# 观史深度条目写作指南

> 本文档是全站条目深度化的唯一标准。写之前先读两遍，动笔时对照自检清单。
> 风格样板：`src/data/figures.js` 的 **孔子** 条目、`src/data/civilizations.js` 的 **唐** 条目。

## 一、达标标准（lint:depth 自动检查，缺一不可）

| 项 | 标准 |
|---|---|
| 正文总字数 | **≥ 1200 字**（目标 1500-2200，宁缺毋滥凑数） |
| 分节 sections | **4-5 个**，每个 heading + 2-3 段 |
| 事实卡 facts | **6-8 张**，含具体数字/年代 |
| 引文 quote | **必须有**：真实可考的原典或时人评语，注明出处；**严禁杜撰** |
| 关联 related | **≥ 4 条**，只能用 all-ids.json 白名单里的 id |
| 出处 sources | 1-3 条（原典维基文库 / 维基百科 / 博物馆页） |

## 二、分类写作框架（sections 的骨架建议，可按人物/事件特点调整）

- **文明 civilization**：崛起缘起 → 制度如何运转 → 高光与开放性 → 衰落转折 → 长程遗产
- **人物 figure**：出身与时代 → 上升与关键抉择 → 核心成就（可两节）→ 死亡/失败 → 身后影响与再评价
- **文物 artifact**：它是什么/怎么被发现 → 工艺与细节 → 功能与主人 → 流传命运 → 意义与现藏
- **事件 event**：背景火药桶 → 经过（有转折，不要流水账）→ 代价 → 直接后果 → 长程影响

## 三、文风十诫（从样板条目提炼）

1. **开头即入戏**：一句话把读者按进现场，不许写「XX 是中国历史上著名的……」这类百科腔。
2. **细节优先**：「编联竹简的皮绳磨断三次」胜过「勤奋读书」；有具体数字、地名、人名就用。
3. **因果成链**：每段说清「所以呢」，事件之间要有推进感，不是词条罗列。
4. **冲突与转折**：每节至少一次「但是/然而」，历史本来就是如此。
5. **收束有力**：每节最后一句要能立住，或余味，或反问，或一句重锤。
6. **不堆辞藻**：删掉一切「波澜壮阔」「源远流长」式的空话。形容词越少，事实越有力。
7. **不虚美不隐恶**：失败、争议、污点照写（孔子一生仕途失败、居里夫人被网暴），人物才立得住。
8. **引文真实**：只用可考证的原典/时人语句；译名与年代以通行说法为准，学界有争议处写「据推测」「一说」。
9. **古今勾连**：适当一两个「今天的」锚点（唐人街、罗塞塔作为隐喻），但每篇最多一两处。
10. **同题不同调**：同文明/同事件系列条目避免句式雷同，读三篇不应觉得出自同一模板。

## 四、格式与硬规则（违反 = 打回重写）

- 输出为**单个 JS 对象字面量 chunk**（不含外层花括号前导）：第一行 `    id: 'xxx',`，最后一行 `  },`
- 字符串一律**单引号**；内容里的单引号写 \'；**禁止**反引号、模板字符串、字符串内真实换行
- `image` 块从 current.json **逐字保留**，一个字符都不要改
- `kicker`（≤10字）与 `summary`（≤30字）可保留或微调，不改功能
- `related` 只用 all-ids.json 白名单；`year`/`range`/`region`/`category` 不改
- 中文引号用「」，避免在字符串里出现未转义的英文单引号

## 五、自检清单（写完每条过一遍）

- [ ] 字数 ≥1200（不含 facts/sources）
- [ ] 4-5 个 sections，每节 2-3 段，每段 100-200 字
- [ ] facts 6-8 张，至少 3 张有具体数字
- [ ] quote 真实可考 + quoteBy 注明出处
- [ ] related ≥4 且都在白名单
- [ ] 单引号转义无误（在脑内跑一遍 JS 语法）
- [ ] 读起来：有画面、有转折、有收束——不像百科词条
